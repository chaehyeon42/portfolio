Troubleshooting Experience

1. EKS - 온프레미스 VPN 연동 및 터널링 무중단 구축

인프라 네트워크 / VPN 프로토콜 규격 통일 및 통신 단절 장애 해결

Infra & Network
  • 문제 상황:
    EKS 파드 내부에서 외부 온프레미스 GPU 서버로의 통신이 거부되고, 방화벽 개방 후 통신이 성공해도 1시간 주기로 터널링이 강제 단절되는 치명적 장애 발생.
  • 해결 과정:

    ① 방화벽 및 라우팅 병목 해결: 온프레미스 우분투 방화벽에서 AWS VPC 대역(10.0.0.0/16)을 전면 허용하고, AWS 정적 라우팅 설정에 로컬 사설 대역을 명시하여 길을 뚫어주었습니다.

    ② IKEv1 인증 규격 충돌 해결: AWS 게이트웨이가 구형 IKEv1 규격으로 세팅된 것을 추적하여, ipsec.conf 설정의 암호화 알고리즘을 AWS 명세서와 100% 강제 동기화했습니다.

    ③ 1시간 주기 단절 해결: 1시간마다 새로운 암호화 키로 교체시 발생하는 단절을 막기 위해 rekey=yes, reauth=no 옵션으로 부드러운 갱신을 유도하고, 1분 주기의 Keep-Alive(Ping) 크론탭을 등록하여 유휴 상태(Idle) 차단을 방지했습니다.

  • 결과 및
    습득 역량:
    끊김 없는 안정적인 Site-to-Site VPN 무중단 통신 환경을 확립했습니다. 이 과정을 통해 블랙박스처럼 여겨지던 네트워크 계층의 암호화 프로토콜(IPSec Phase 1/2) 동작 방식을 저수준에서 분석하는 역량을 내재화했으며, 하이브리드 클라우드 인프라 설계 능력을 극대화했습니다.

2. GPU AI 서버 SSH 무차별 대입 공격 대응 및 인프라 보안 강화

하이브리드 관제 환경에서 외부 노출 서버의 브루트포스(Brute-force) 차단

Security & Network
  • 문제 상황:
    AI 영상 처리 및 모델 학습을 수행하는 외부 GPU 서버 와 AWS 인프라 간 연동 작업 중, GPU 서버의 SSH 접속이 간헐적으로 지연되거나 튕기는 현상 발생.
  • 원인 추적:

    ① 로그 분석(auth.log): 시스템 로그를 정밀 분석한 결과, 외부 인터넷망에 노출된 GPU 서버의 SSH 포트를 대상으로 해외 봇넷(70여 개 IP)의 브루트포스(Brute-force) 무차별 대입 공격이 집중되고 있음을 확인.

    ② 쓰로틀링(MaxStartups) 병목: 10시간 동안 무려 162만 건 이상의 인증 시도가 MaxStartups 제한에 걸려 드롭되었으며, 이 방대한 공격 트래픽이 동시 연결 슬롯을 잠식해 팀원들의 정상적인 개발 및 연동 작업까지 방해하고 있었음.

  • 해결 및
    개선:
    최소 권한 원칙을 바탕으로 GPU 서버의 방화벽 정책을 정비하여 불필요한 외부 인바운드 접근을 전면 차단하고, 신뢰할 수 있는 VPN 대역 및 내부망에서만 SSH 포트에 접근하도록 네트워크 대역을 엄격히 제한함. 이를 통해 비정상적인 인증 요청을 원천 차단하고 안정적인 개발 및 통신 환경을 확립함.

3. CloudFront 및 ALB 환경의 HTTP 503 및 Mixed Content 에러 해결

쿠버네티스 헬스체크 및 HTTPS 프로록시 보안 정책 충돌 해결

Cloud & DevOps
  • 문제 상황:
    React 대시보드에서 로그인 또는 카메라 영상을 호출할 때 HTTP 503 Service Unavailable 및 Mixed Content 에러가 발생하여 실시간 통신 및 영상 렌더링이 전면 마비됨.
  • 해결 과정:

    ① 503 에러 (ALB 헬스체크 실패): EKS 백엔드 파드는 정상이나 ALB 대상 그룹 상태가 Unhealthy로 떨어짐을 확인. K8s Manifest의 Health Check 경로를 /actuator/health로 교정하고, EKS 노드 보안 그룹에 ALB의 8080 포트 인바운드를 오픈하여 트래픽 전달을 복구했습니다.

    ② Mixed Content 및 CORS 에러: 클라우드의 HTTPS 웹사이트가 온프레미스의 HTTP(8010~8014 포트) 영상을 직접 호출하면서 발생하는 보안 차단을 막기 위해, AWS CloudFront를 도입하여 HTTPS로 중계했습니다.

    ③ ALB 대상 그룹 라우팅 분기: CloudFront의 /mjpeg/* 요청을 AWS ALB로 넘기고, ALB의 대상 그룹을 IP Type으로 설정하여 온프레미스 GPU 서버(공인 IP)의 각 포트별로 정밀하게 라우팅 분기 규칙을 생성했습니다.

  • 결과 및
    습득 역량:
    네트워크 라우팅 규칙과 CDN 캐시/보안 정책을 결합하여 영상 송출 성공률 100%를 달성했습니다. 이를 통해 웹 브라우저의 최신 보안 정책(PNA, CORS)과 클라우드 로드밸런싱 계층 간의 상관관계를 통제하는 트러블슈팅 역량을 습득했습니다.

4. 풀스택 ERP 통합 테스트 중 발생한 DTO 매핑 및 경로 충돌 장애 해결

React 프론트엔드와 Spring Boot 백엔드 연동 과정에서의 API 통신 오류 극복

Fullstack & API
  • 문제 상황 :

    ① 로그인 시 400 Bad Request 에러 발생

    ② 로그인 직후 user.role 읽기 실패로 인한 화면 마비

    ③ 연차 목록 조회 시 /api/v1/api/v1/... 경로 중복 및 500 에러가 동시 다발적으로 발생함.

  • 해결 과정:

    ① DTO 필드명 동기화: 프론트엔드에서 전송하는 객체 키명을 백엔드 DTO 규격과 정확히 일치시켜(userId, password) 400 에러 해결.
